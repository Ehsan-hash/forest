## Evidence methods

- **REAL API:** ordinary application endpoints persist actual identities, revisions, bytes or receipts on the isolated backend, confirmed by readback. Test setup through API is identified when the corresponding browser action was not exercised.
- **REAL WORKER:** the ordinary scheduler/worker executes a provider-free task and produces the observed state/output/artifact. A queued receipt alone is insufficient.
- **BROWSER:** actual rendered controls, navigation, editing, keyboard interaction or local preferences are observed.
- **FAULT:** a real response is held/aborted or a failure response is injected. This proves recovery for that condition, not real execution of a fabricated outcome.
- **MOCK:** selected endpoint responses contain fabricated runs, decisions, rows or files. Real disposable project ownership does not turn the fabricated data into real evidence.
- **UNIT / BACKEND TEST:** helper/markup or isolated backend assertions. These supplement browser acceptance; neither substitutes for an unexecuted browser journey.

**PASS** records the stated observable. **PARTIAL PASS** records a verified subset and the missing condition. **MOCK UI PASS / REAL NOT RUN** records fixture presentation only. **PENDING RETEST** records a known failure with a source/test correction awaiting executed evidence. **NOT RUN** means no qualifying executed evidence is recorded.

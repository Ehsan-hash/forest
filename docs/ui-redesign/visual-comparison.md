## Performance evidence

An isolated Vite production build of the clean original `ff16c3f` source used the same current installed frontend dependencies as the redesign and wrote into a new temporary directory. Its retained [build log](evidence/baseline-bundle.txt) records exit 0 and a clean original checkout afterward. It did not replace the running production assets. [Exact bundle measurements](evidence/bundle-comparison.json) record the initial index JavaScript and default Node gzip compression: original 694,362 bytes / 217,261 gzip bytes; final build 63005 410,121 bytes / 128,162 gzip bytes, reductions of **40.94%** and **41.01%** respectively.

This measures initial index JavaScript rather than total dependency/route chunks. Monaco, PDF and scientific rendering dependencies still have separate costs. A before/after runtime FCP comparison was **NOT RUN**; original Vite development timing is not used as a production performance claim.

PDF previews now use an owned abortable HTTP read before constructing the PDF.js worker from complete bytes. This removes the reproduced worker termination error when the shared pane closes during loading. The final real-worker manuscript test passed 12 delayed GET cancellations, subsequent canvas-ink rendering, current/stale export checks and zero page errors; [its lifecycle receipt](evidence/pdf-preview-lifecycle.json) retains the result. The identical 16-cycle read-only probe changed from six page errors to zero. The tradeoff is that first PDF display waits for the complete download rather than using PDF.js URL streaming/range startup. Large-PDF startup timing was **NOT RUN**.

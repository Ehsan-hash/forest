# UI-to-API coverage

Baseline source: `ff16c3f656f94d053d1bba65c6b3a07a5feaccde`, inspected 2026-10-13. This matrix traces existing handlers and generated contracts. Baseline rows are **SOURCE INSPECTED / RUNTIME NOT RUN**; the implementation update below records actual intervention validation and newly reachable source-confirmed actions. The existence of a handler or old spec is not a pass.

The canonical [API coverage index](api-coverage.md) links to this complete matrix; action/request details are maintained here as one source.

API paths below omit the `/api` prefix unless marked WebSocket. `P`, `N`, `B`, `R`, `D`, and `V` denote complete project, node, branch, run, paper document and resource IDs. These identities are not interchangeable merely because their wire type is string. Template `{ident}` means the row's named identity. Contract response names refer to `packages/contracts/openapi.json` and `api.generated.ts`. `Json` means the actual extensible direct response, not an invented data envelope.

For reads, `useLoad` guards path and request generation. Shared project SSE invalidates server snapshots through `forest-refresh`; events do not themselves prove a mutation/execution/evidence outcome. JSON writes use `api` or typed `requestApi`; neither retries automatically. `UIContext.action` catches a rejection and returns undefined after feedback, so a caller must not clear a draft or announce success simply because the wrapper returned. New JSON operations should use the typed client. Blob downloads, EventSource and PTY WebSockets remain separate.

## Mandatory invariant readback

Execution status, source-bound verification, current Goal applicability and purpose acceptance are four independent facts. Artifact presence, model connection, a request receipt, finished run and publication readiness each require their own actual readback. A historical retry preserves its original node revision/config/provider snapshot and must not become current solely because it has the newest timestamp. `latest_run_id`, result-current flags and rerun generation remain server authority.

Run output uses the returned byte cursor. Table offsets are row counts. File writes use loaded path revisions including delete/recreate generations; graph/node writes use graph/project revision; resource/figure/paper writes use their own revision. A changed request intent gets a new request ID; a lost response for the same supported pending intent keeps its original ID. No automatic network retry should duplicate a mutation.

Downloads require observed HTTP response, actual MIME/file presence/size and expected contents. Current manuscript PDF requires compiled_revision equal to paper revision and explicit format:pdf export; raw pdf_path presence is insufficient. A local arithmetic artifact journey validates runtime plumbing and provenance, not a scientifically publishable improvement.

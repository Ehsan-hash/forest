## Architecture decisions to verify during implementation

1. Keep the server snapshot owner separate from editable drafts. Share complete node/paper edit sessions where surfaces unmount or change, without adding a second authoritative resource cache.
2. Keep graph mutation serialization and pending-position flush in one owner. Do not replace the established lost-position-response receipt replay with an optimistic version counter.
3. Use stable object IDs and route query state for intended selections. Missing requested objects must remain missing instead of silently selecting the first available object.
4. Preserve first-class entries for all existing operations. Grouping reduces navigation density; it does not remove ideas, theory, branches, evidence, logs, terminal, import/export/share, or provider administration.
5. Measure browser rendering, navigation and heavy-surface behavior after implementation. No performance improvement is claimed by these source counts or proposed component extractions.

## Added analysis component boundary

`WorkspacePage.tsx` wires the shared right-side Analysis/Paper panel, hide/pin/resize/expand and node-edit transitions. `ResearchAnalysisPanel.tsx` owns context preview, explicit scoped request, history selection and source-bound report/citation rendering. `researchAnalysisDraft.ts` owns per-project/scope/target session drafts, reviewed revision/fingerprint/provider, retained request intent and safe external citation URLs. All six analysis cases pass in the final 108-case production suite, including actual scope reads, independent drafts, strict input/reference dependency semantics, explicit source re-review and citation import; transport/report fixtures are labelled. The earlier shared-session target passed 10/10. Final scoped two-theme analysis review is complete in [RA5](test-matrix.md#added-analysis-acceptance); broader Pin/resize keyboard and complete overlay traversal remain NOT RUN.

`services/api/research_analysis.py` owns preview/submission/history/result endpoints and saved-intent/revision guards. `research/planning/workspace_analysis.py` builds the full recorded context, retrieves server-owned citations, validates report IDs/coverage/judgments and writes advisory Analysis records. Existing scheduler/worker/model transport own provider selection, spending and actual execution. Analysis has no TaskRun Node/Branch binding and cannot replace experiment status, latest result, controller decisions or measured metrics. [A58](ui-api-coverage.md#added-scope-workspace-research-analysis--a58) and the [analysis acceptance extension](test-matrix.md#added-analysis-acceptance) distinguish real backend/worker transport from authored model output and unexecuted live AI quality.

Context includes complete same-project version/intervention history, source passages, non-analysis tool receipts, ordered scientific events and file revisions. All five added resource models and their IDs/relationships are exercised by the latest 13-case backend retest; foreign history is excluded, and an effect-only update rejects the earlier fingerprint without changing project revision. The frontend exposes saved resources and complete tool/event/version/dependency details; these are recorded receipts, not a claim that every effect was delivered or a model read every material byte.
